Studio UI design

IntelliJ’s brain, Apple’s body, and a seat at the table for agents.

Studio is a macOS IDE where you and several agents work on the same code at once. This design covers ARCHITECTURE §11.1, §11.3, §16, Appendix A rows U01–U07 and C09–C12, and the collaboration surfaces proposed in Design 1 §12 (presence, the Needs-you queue, the ask-human tool, Mission Control). Dark appearance is shown throughout; the light values sit next to every token.

1. Design intent

01

Calm canvas, live edges

The editor stays quiet and opaque. Agent activity lives at the edges (tool windows, gutter, status bar, toolbar pill) and comes forward when you ask for it.

02

Every change has a face

Wherever code or a diff appears, its author is visible by shape, color, and name: you, an agent session, Studio, or something external.

03

Agents are colleagues, not pop-ups

Agents have names, presence, status, and a conversation. They show up like teammates in a shared document, not as modal dialogs.

04

You hold the pen

Nothing reaches your main tree without your acceptance unless you chose in place. Risky actions ask first. Reverting agent work is one click.

05

Attention is a queue, not a siren

One Needs-you queue collects approvals, questions, reviews, and failures, and you can triage it from the keyboard. Nothing steals focus while you type.

06

Keyboard first, mouse friendly

Every flow completes without a pointer. JetBrains-compatible keymap by default.

07

Native first

Real macOS menus, sheets, popovers, vibrancy, and SF fonts. Web imitations only where the host cannot do better.

08

Accessible by construction

Never color alone. Contrast is checked numerically. Reduce Motion, Reduce Transparency, and Increase Contrast are honored.

The most important visual system in the product. It answers “who wrote this?” without hovering, without color, and without reading.

  • Confidence. Anything not certain (for example a CLI started by hand without the opt-in hook) shows its gutter mark at reduced opacity, adds “likely” to the line card, and keeps the shape. Ambiguous changes use a dotted outline. Try turning off precise tracking in the prototype’s Settings: the marks fade.
  • Session hues. Each running agent session gets a hue for its presence cursor, card, and console header: ◆ violet, ◆ pink, ◆ cyan, ◆ lime, ◆ orange, assigned round-robin. The diamond never changes. In the gutter every agent mark is violet, because the gutter answers “agent or me?”; the line card names the session.
  • Shapes first, color second. All five gutter marks stay distinguishable in grayscale and for every common color-vision deficiency.

Every value below is read from tokens.css, the file task T10 copies into app/ui/src/theme/tokens.css. 8. Key flows

F1 · Delegate and review

  1. ⌘⇧Y opens Delegate with the selection as context.
  2. Worktree and Propose, then Delegate. A card appears in Mission Control.
  3. When it finishes, Review ready enters the queue.
  4. Review Inbox: J/K through hunks, A/X, then Apply.
Try it in S3 →

F2 · Pair in a terminal

  1. Type claude in a terminal; the tracking banner appears.
  2. The agent’s edits show live: presence cursor, violet gutter marks.
  3. AI Changes counts climb; review turn by turn on the timeline.
Try it in S10 →

F3 · Approve a risky command

  1. The Needs-you count rises with one soft pulse; focus stays where it is.
  2. Open the queue when ready: command, reason, risk.
  3. “Allow for this session” or “Always allow” stores a rule you can revoke in Settings.
Try it in S6 →

F4 · Answer a question

  1. The question appears in the queue and on the agent’s card.
  2. Pick an option or type an answer.
  3. The agent carries on; the item resolves.
Try it in S7 →

F5 · Revert one agent change next to your edit

  1. Click the violet gutter mark, then “Revert this change”.
  2. A 3-way revert keeps your neighbouring lines; an Undo toast offers the safety checkpoint.
  3. If the change overlaps your edit, Studio refuses and points you to the merge view.
Try it in S1 →

F6 · Contested save

  1. The agent edits a file you have unsaved changes in.
  2. Banner: “Claude changed this file 3 s ago. Saving will merge.”
  3. On save, a clean merge writes silently; a conflict opens the merge view.
See the banner in S1 →

F7 · Parallel agents

  1. Three tasks run in separate worktrees.
  2. Mission Control shows three cards in distinct session hues.
  3. Each has its own AI Changes view, with no cross-attribution.
Try it in S2 →

F8 · Learn with a tutor

  1. Open a lesson; Studio scaffolds the exercise in a worktree and attaches the tutor.
  2. Check runs the exercise’s own tests.
  3. Ask for a hint; fix the code yourself; Check again.
Try it in S12 →

No agents runningThe pill hides; Mission Control shows “No agents running. Delegate a task or run an agent CLI in a terminal.”

Low-confidence attributionFaded mark and “likely” in the line card; nothing is hidden.

11. Accessibility

  • Contrast. The token tables meet WCAG 2.x AA: 4.5:1 for text, 3:1 for controls, focus, and session hues. Increase Contrast swaps hairlines for control borders and tertiary text for secondary.
  • Never color alone. Actor shapes, +/− signs in diffs, text labels on every status.
  • VoiceOver. Every glyph has a spoken label; gutter marks say “line 20, written by Claude, then edited by you”. Agent state changes use a polite live region; nothing is assertive except an approval you opened yourself.
  • Focus. Approvals, questions, and toasts never take focus. Focus order follows the layout; every tool window is reachable by shortcut and Tab. After deciding a hunk, focus stays on that hunk.
  • Motion. With Reduce Motion, presence carets and pulses stop, panels appear without sliding, and the timeline jumps instead of easing.
  • Transparency. With Reduce Transparency, vibrancy materials become solid chrome and panel surfaces.
  • Text size. UI 11–17 pt through the font-size setting, code 10–24 pt; layouts reflow without clipping.

12. Writing for the UI

  • Name agents by session title (“token-refresh”), with the CLI where it matters (“Claude · token-refresh”).
  • Use plain status verbs: “Editing session.ts”, “Running npm test”, “Waiting for your approval”, “Ready for review”.
  • Say Needs you, not “Pending”. Say agent, not “AI says”.
  • Numbers carry meaning: “3 files · +28 −4 · 5 hunks to review”.
  • Notifications: “Claude changed 3 files (+28 −4). Open AI Changes.” · “checkout-tests wants to run npm install. Review.” · “rate-limit is ready for review: tests passed.”
  • Errors say what happened and what to do: “Claude CLI wasn’t found on PATH. Install it or set its path in Settings → Agents.”
